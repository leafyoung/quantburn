# quantburn benchmark & cross-validation suite

Compares four backends on identical quant workloads:

| # | Stack        | Backend                | How to run |
|---|--------------|------------------------|------------|
| 1 | torchquantlib| torch CPU              | system python3 (torch 2.13+cpu) |
| 2 | torchquantlib| torch ROCm (HIP, gfx1151 Strix Halo iGPU) | `~/devv/study/study-rl-0dte/.venv/bin/python` (torch 2.12.0a0+rocm7.13; config mirrors `refs/tf-quant-finance/pyproject.toml`: rocm-nightly gfx1151 index, `import rocm_sdk; rocm_sdk.initialize_process()` before framework import — the tf-quant `conftest.py` recipe) |
| 3 | quantburn    | Burn NdArray (CPU)     | `cargo run --release --bin bench -- --backend cpu` |
| 4 | quantburn    | Burn Wgpu/Vulkan       | `cargo run --release --bin bench -- --backend vulkan --features vulkan` |

## Two modes

- **check** — correctness. Every backend computes every workload from the SAME
  inputs (shared `.npy`/`.bin` files under `bench/data/`, generated once by
  `bench/gen_inputs.py` from a fixed seed). Pairwise comparison across all four
  backends: max |a−b| and max relative diff, against per-workload tolerances
  (f32 MC: rel ≤ 1e-3 vs f64 anchor; closed-form f32: rel ≤ 1e-5; tensor matmul:
  rel ≤ 1e-4). MC workloads use f64 accumulation of the mean where the Python
  library does, and the anchor is the system-torch CPU result computed in f64.
- **bench** — timing. Per workload: 2 warmup runs + N timed runs
  (workload-specific), report min/median wall time. Python: `time.perf_counter`.
  Rust: `std::time::Instant`. GPU backends synchronize before stopping the clock
  (`torch.cuda.synchronize()` / burn ops block on completion for Wgpu readback —
  every workload ends in a `.into_data()`/`.item()` readback or equivalent).

All workloads run in **f32** (the common denominator: quantorch torch code is
f32 by default; Burn Wgpu/Vulkan on gfx1151 targets f32 — f64 on RDNA3.5 iGPU
is emulated and >100× slower). MC cross-implementation parity is via shared
normals, not shared RNGs.

## Workloads (shared spec — both harnesses MUST implement exactly this)

| id | name | exact spec | timed metric | anchor tol (check) |
|----|------|-----------|--------------|--------------------|
| W1 | bsm_grid | BSM call price for 200 spots × 200 vols (grid 40k, K=100, T=1, r=0.05, q=0), spot 50..150, vol 0.05..1.0 | ms | rel 1e-5 |
| W2 | implied_vol | bisection IV (tol 1e-8, ≤100 iters) for 2000 prices from vols 0.05..1.5, S=K=100 T=1 r=0.05 | ms | rel 2e-4 |
| W3 | binomial_american | CRR American put, S=100 K=100 T=1 r=0.05 σ=0.2, N=2000 steps | ms | rel 1e-5 |
| W4 | mc_european | GBM Euler... exact: S_{t+1}=S_t*exp((r−σ²/2)dt+σ√dt·Z), Z from shared file `mc_euro_normals.f32` shape [100_000, 100], S0=100 K=100 T=1 r=0.05 σ=0.2; discounted mean call price | ms | rel 1e-3 |
| W5 | mc_asian | same dynamics, Z from `mc_asian_normals.f32` [50_000, 64], dt=1/64, arithmetic average incl. S0, discounted mean call | ms | rel 1e-3 |
| W6 | heston | full-truncation Euler: v_{t+1}=max(v_t+κ(θ−v_t)dt+ξ√(v_t dt) Zv,0), S via exp((r−v_t/2)dt+√(v_t dt) Zs), Zs/Zv from `heston_zs.f32`/`heston_zv.f32` [20_000, 250], S0=100 v0=0.04 κ=2 θ=0.04 ξ=0.3 ρ=−0.7 (ρ via Zv'=ρZs+√(1−ρ²)Zv), T=1, discounted E[max(S−K,0)] K=100 | ms | rel 2e-3 |
| W7 | cir_sim | CIR terminal sample: x=x+κ(θ−x)dt+σ√(x dt)Z, floor 0, Z from `cir_normals.f32` [50_000, 250], x0=0.05 κ=0.5 θ=0.05 σ=0.1 T=1; mean + std of terminal x | ms | rel 2e-3 |
| W8 | greeks_fd | pathwise MC delta+vega of W4's option: d/dS0, d/dσ via common-random-numbers on the SAME `mc_euro_normals.f32`, central diff h_S=1e-2·S0, h_v=1e-4 | ms | rel 2e-3 |
| W9 | var_es | historical 95%/99% VaR (linear-interp quantile) + ES on shared `var_losses.f32` [1_000_000] | ms | rel 1e-6 |
| W10 | mlp | 8×512 MLP, batch 16384, input dim 32: forward + backward, loss = mean squared output sum; weights from seed (same values all backends, file `mlp_weights.f32` laid out layer-major [in_dim×512, 512×512×7, 512×1]) | ms | rel 1e-3 |

Shared input files (generated by `bench/gen_inputs.py`, seed 7, torch CPU
f64→f32 normals, C-order, written as raw little-endian f32 `.f32` plus a
`shapes.json`): `mc_euro_normals` [100000,100], `mc_asian_normals` [50000,64],
`heston_zs`/`heston_zv` [20000,250], `cir_normals` [50000,250],
`var_losses` [1000000], `mlp_weights` (flat, dims in shapes.json).

## Files

- `bench/gen_inputs.py` — writes `bench/data/`
- `bench/bench_quantorch.py` — `--mode check|bench --device cpu|cuda [--workloads W1,W2] [--iters N]`
  (run under the rl-0dte venv for ROCm; script does the rocm_sdk init dance
  itself, defensively)
- `src/bin/bench.rs` — `--mode check|bench --backend cpu|vulkan [--workloads ...] [--iters N]`
- `bench/run_all.sh` — runs all four, writes `bench/results.md` (timings table
  + pairwise check matrix)
