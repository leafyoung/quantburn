# quantburn — AGENTS.md

Rust/Burn port of [`../quantorch/torchquantlib`](../quantorch) (Python/PyTorch
quant pricing library). Read this before touching the crate.

## What this is

- **Per-file port**: one Rust module under `src/` per Python source file under
  `torchquantlib/`. The `//!` doc header of each module names its Python
  original. A full mapping table lives in `README.md`.
- **121 embedded parity tests** (`#[cfg(test)]` in each module), all green:
  `cargo test --lib`. Expected values are literals generated by the committed
  Python reference scripts — no test depends on runtime RNG.
- **A 4-backend benchmark / cross-validation harness** under `bench/` (see
  below).

## Implementation details an agent must know

- **Shared deterministic RNG** (`src/rng.rs`): xorshift64* + Box-Muller,
  bit-exact-parity-verified against `scripts/refgen.py`. Monte-Carlo parity
  with Python works by drawing *identical normals* on both sides — never by
  matching torch's RNG (impossible). Modules that simulate use documented
  fixed seeds (vasicek 2002 … dupire 2009, greeks 3001, exotics 1234+).
- **Shared helpers — reuse, don't re-implement** (added in the post-port
  cleanup pass):
  - `lmm::cholesky` — the one Cholesky factorization (asserts positive
    definiteness); used by exotics, greeks, lmm.
  - `black_scholes_merton::{erf, normal_cdf}` — the accurate (~1e-15) erf;
    used by letsberational too. sabr.rs/structural_model.rs keep their own
    erfc variants (different tail requirements).
  - `option_utils::{calculate_binomial_tree_params, option_payoff,
    price_binomial_tree, binomial_tree_batch}` — the single CRR tree;
    `binomial_tree_model` delegates to it.
- **Error-handling convention**: `Result<_, String>` for user-input
  validation (mirrors Python `ValueError`); panic/`assert!` only for internal
  invariants. Individual modules stay faithful to their Python source's
  behavior.
- **Deliberately preserved Python quirks** (do not "fix" them):
  - `letsberational` implied-vol bisection always prices a call internally;
    `is_call` only gates the no-arb bound.
  - `greeks::MalliavinGreeks` weights are unnormalized (the Python library
    genuinely outputs delta ≈ 93 for an ATM European call).
  - lookback floating-strike put *and* call payoffs are identically 0 in the
    source; the port preserves this and the tests document it.
  - ES includes the `1e-6 * VaR` stabilizer; Vasicek's `kappa*T >= 1` mean
    collapse branch, etc.
  - `greeks` digital tests use epsilon=2.0 because the Python default 1e-4
    makes every estimator numerically zero (weakness in the Python code).
- **Not converted** (no portable numeric core, on purpose):
  `torchquantlib/calibration/*`, `utils/seq2seq_pde_solver.py`, and the
  training loop of `models/stochastic_volatility/gans.py` (its forward-pass
  core *is* ported in `src/gans.rs`).
- Conversion rules for new modules: `CONVENTIONS.md`.

## Validation

Two layers, run both after any change:

```bash
# 1. embedded parity tests (fast; the workhorse)
cargo test --lib                     # 121 passed, 0 failed

# 2. examples compile + run
cargo build --examples
cargo run --example black_scholes_merton   # ATM-adjacent sanity values
```

Full cross-stack validation (all four backends, same inputs):

```bash
bench/run_all.sh
```

Parity methodology: deterministic closed-form modules compare against pure-f64
Python references (`scripts/gen_<module>.py`, run with system `python3`,
torch available) at 1e-8…1e-14; stochastic modules compare full pipelines
given identical normal draws, at ~1e-6; f32 GPU backends vs the f64 anchor
carry documented wider tolerances where f32 rounding is the floor (see
`bench/results.md` notes — e.g. W1's ~1e-28 deep-tail BSM prices cancel, and
W3's 2000-step f32 tree accumulates ~6e-5 relative rounding).

## Benchmark setup

Four stacks, one workload spec (`bench/DESIGN.md`, W1–W10 — BSM grid, implied
vol, CRR tree, MC European/Asian, Heston, CIR, FD greeks, VaR/ES, MLP fwd+bwd):

| stack | how |
|---|---|
| torch CPU | system `python3` (torch 2.13+cpu) |
| torch ROCm (HIP) | `~/devv/study/study-rl-0dte/.venv/bin/python` — torch 2.12.0a0+rocm7.13 on the Radeon 8060S (gfx1151 Strix Halo). Config mirrors `/var/home/yangye/devv/qfin/refs/tf-quant-finance` (rocm-nightly gfx1151 index); the `rocm_sdk.initialize_process()`-before-import recipe is tf-quant's `conftest.py`. |
| burn CPU | `cargo run --release --bin bench -- --backend cpu` (NdArray) |
| burn Vulkan | `cargo run --release --features vulkan --bin bench -- --backend vulkan` (burn-wgpu, API pinned to Vulkan) |

- Modes: `--mode check` (correctness; pass criterion = *global* relative diff,
  mirroring `bench_quantorch.py`; per-element rel is meaningless near zero) and
  `--mode bench` (2 warmups + `--iters` timed runs, GPU-synced readback).
- All stacks consume identical inputs from `bench/data/*.f32`
  (`bench/gen_inputs.py`, seed 7). All workloads run f32 (the common
  denominator; f64 is emulated and >100× slower on this iGPU).
- Everything f32 runs on shared inputs; only W10's Rust-side MLP weights differ
  from Python by design (torch's MT19937 stream isn't reproducible outside
  torch — the Rust harness draws from a documented mulberry64 stream).
- Results of the last full run: `bench/results.md` + JSON in `bench/results/`.
- Known performance shape: burn-Vulkan dominates tensor-heavy workloads;
  torch-ROCm is kernel-launch-latency-bound on many-small-step sequential
  simulations; burn-CPU (NdArray, no threaded BLAS) is the slow portable path.

## Crate mechanics

- burn 0.20, `default-features = false, features = ["ndarray", "autodiff"]`;
  `burn-wgpu` only behind the optional `vulkan` feature. Default build must
  stay CPU-only and green.
- `src/bin/bench.rs` is the only binary; `src/main.rs` was removed.
- The workspace uses a shared cargo target dir (`~/.cache/rust-build`), so
  `target/` here stays nearly empty.
- The 21 cargo examples in `examples/` mirror `../quantorch/examples/*.py`
  1:1 by name; training-loop-only Python examples are adapted to the portable
  numeric core with an explanatory doc comment.
